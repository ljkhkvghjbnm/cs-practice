## Шаг 1: три состояния проекта

Создан калькулятор calc.py, развитый тремя коммитами:

1. Коммит 1:
   Команда: `git add calc.py`
   Команда: `git commit -m "Add addition to calculator"`
   Действие: добавлена функция сложения в calc.py.

2. Коммит 2:
   Команда: `git add calc.py`
   Команда: `git commit -m "Add subtraction to calculator"`
   Действие: добавлена функция вычитания в calc.py.

3. Коммит 3:
   Команда: `git add calc.py`
   Команда: `git commit -m "Add multiplication to calculator"`
   Действие: добавлена функция умножения в calc.py.



git diff показывает разницу между состояниями.

git show показывает изменения, сделанные в конкретном коммите.

git log показывает историю коммитов.

git log -S ищет коммиты по вхождению строки в изменения.

git blame показывает для каждой строки файла: кто её написал и когда.


git restore <file> возвращает файл к состоянию последнего коммита (HEAD).

git restore --source=<commit> <file> возвращает файл к состоянию указанного коммита (например, HEAD~2).

Если у вас были несохранённые правки в файле, они будут потеряны после выполнения git restore



## Шаг 4: отмена ошибочного коммита

Выполненная команда: `git revert HEAD`
Результат: Git создал новый коммит, который отменил изменения предыдущего коммита. Ошибочный коммит остался в истории.
Отличие от `git reset --hard`:
  - `git revert` **добавляет** новый коммит, отменяющий предыдущий. История не переписывается — безопасно для общих веток.
  - `git reset --hard` **удаляет** коммиты из истории. Опасно, если ветка уже отправлена на GitHub — может сломать работу других разработчиков.
Почему `revert` безопаснее:
  - Не меняет уже опубликованные коммиты.
  - Позволяет отследить, какие изменения были отменены и почему.
  - Подходит для командных проектов.
