## Рабочая папка (Working Directory)
Это папка на моём компьютере, где я пишу код. Здесь лежат все файлы проекта. Git видит изменения, но пока не запоминает их навсегда.

## Индекс (Staging Area)
Это как «корзина» или черновик коммита. Команда `git add` кладёт изменения сюда. Это значит: «Я хочу включить эти правки в следующий снимок истории».

## Коммит
Это зафиксированный снимок проекта. Когда я делаю `git commit`, Git сохраняет состояние файлов из индекса как отдельную версию. У каждого коммита есть сообщение, которое объясняет, зачем он сделан.

## Git и GitHub

- **Git** — это программа на моём компьютере. Она хранит историю изменений локально.
- **GitHub** — это сайт, где хранится копия репозитория. Туда я отправляю историю, чтобы её видели другие и чтобы было резервное хранилище.

### Команды diff

- `git diff` — показывает изменения между рабочей папкой и индексом (то, что я изменил, но ещё не добавил).
- `git diff --staged` — показывает изменения между индексом и последним коммитом (то, что готово к фиксации).

## Использованные команды

- `git status` — показывает состояние файлов: какие изменены, какие в индексе, какие новые.
- `git diff` — сравнивает рабочую папку и индекс.
- `git diff --staged` — сравнивает индекс и последний коммит.
- `git commit -m "..."` — создаёт коммит с сообщением.
- `git push` — отправляет историю на удалённый сервер (GitHub).

## Ветки
Ветка — это указатель на конкретный коммит. Ветка позволяет вести параллельные линии разработки.
При создании нового коммита в текущей ветке её указатель автоматически сдвигается вперёд на этот коммит.
Слияние (merge) объединяет изменения из одной ветки в другую. Оно создаёт связь между историями веток и делает изменения доступными в целевой ветке.
